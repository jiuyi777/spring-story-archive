# 春序档案

面向 SillyTavern 1.14.0 的自动剧情记忆扩展。当前版本为 0.7.1：每轮读取剧情、生成简短事实并更新八类表格，供下一次续写、剧情选项、NPC 和自主推进共同使用。

已安装用户在酒馆扩展管理中点击春序档案的更新按钮，再刷新页面。

## 0.7.1 简化楼层发送

- 默认只显示楼层、回复状态和查看入口。
- 展开先看本次使用的记忆；选择原因、原文及核对信息收进更多详情。
- 楼层发送正文附带方正新书宋字体文件。

## 0.7.0 界面与发送记录

- 三个主页面：数据库、楼层发送、设置。每次打开默认进入中间的楼层发送。
- 数据库支持分类、搜索、可读档案与折叠编辑；人物档案附带其物品和关系。原楼层摘要、总摘要和 NPC 档案继续保留在数据库中。
- 每次正常生成、继续、重选分别保存在当前聊天的发送记录中。可展开查看拦截阶段的原文范围、过滤楼层、表格调用原因，以及插件加入的完整摘要与召回文字。记录不含 API 配置及密钥。
- 状态分别为准备内容、核对待发请求、收到回复、停止或结束未确认。核对以宿主最终提示词事件为依据，不冒充服务商网络回执；原文范围在拦截阶段采集，之后可能受宿主或其他扩展处理。安装前的发送无法还原。
- 表格先按当前场景、明确提及、别名、归属和人物关系选择，再按预算发送；语义回忆可补充相关往事。这是可检查的规则关联，不保证消除模型提取或复杂指代错误。
- 设置集中管理自动记忆、选项写法与数量、写作要求、自主推进、NPC 生成、多个 API 和高级召回参数。
- 开启剧情选项后，角色回复完成会自动生成选项并挂在该回复正文下方；点击只填入聊天输入框。最新回复的选项可在刷新后恢复，编辑、重选、换聊天时核对来源，过期选项不沿用。
- IndexedDB 升级到第 4 版，新增独立发送记录存储，旧档案保持原位。若提示旧标签页占用，请关闭旧酒馆标签后刷新。

## 0.6.0 记忆链路

- 八类表格：时间地点、人物档案、人物关系、物品资源、能力技能、任务进度、线索约定、剧情记录。每轮保存有来源的字段变更，后续只覆盖明确变化的字段。
- 楼层摘要是剧情事实记录；“继续”等纯操作指令保留在本地，不调用总结接口，不生成时间地点、人物状态或写作解说。
- 选项、NPC 和推进读取同一份当前记忆；执行前等待待整理的新剧情。正常续写读取已经成功保存的当前状态及总摘要，未覆盖的原文继续保留。
- 表格可直接编辑、添加和删除，修订保存在当前聊天。楼层编辑、重选或删除后，其过期事实退出当前状态。剧情记录的手动修改同步进入总摘要、续写与语义召回。
- 自动更新可设置轮数和 token 门槛；旧楼层使用“补全下一批”迁移。额外 API 可保存并切换多套配置。
- 模型响应格式异常时自动重试一次；再次失败显示具体错误，保留原文与此前成功的记忆。程序仍须校验模型输出才能安全写入表格，用户不需要编写 JSON。
- 本版使用浏览器本地数据库和直接提示词注入；尚未实现世界书同步或任意自定义表格模板。

## 安装与更新

1. 在 SillyTavern 的扩展页面选择“安装扩展”，粘贴仓库地址：`https://github.com/jiuyi777/spring-story-archive`。
2. 已安装的用户，在扩展管理中找到“春序档案”并点击更新，然后刷新酒馆页面。
3. 打开聊天，点击“春序”悬浮球。设置中的高级项默认开启“每次回复前发送总摘要”和“过滤已摘要的旧楼层原文”，语义回忆可保持关闭。
4. 旧摘要会显示“待核对覆盖”，对应原文继续保留。需要恢复旧楼层过滤时，点击“补全下一批”；这会使用所选 API，产生相应模型用量。

[版本下载与更新说明](https://github.com/jiuyi777/spring-story-archive/releases/latest)。手动安装 ZIP 时，将包内文件放入酒馆的 `public/scripts/extensions/third-party/spring-story-archive/`，确认该目录下直接存在 `manifest.json`，然后刷新页面。

如果没有显示新版本，先确认更新成功并刷新页面；如果摘要失败，查看楼层错误状态及所选 API 配置。默认关闭的手动备用正则不需要启用。浏览器本地档案请保留，更新不需要清理站点数据。

## 已实现的产品规则

- 正常回复前默认读取当前聊天的剧情总摘要，通过独立的系统提示词注入；语义回忆关闭也能使用。摘要页先显示准备了多少楼摘要、过滤多少楼原文，再在酒馆组装待发请求后核对完整摘要。核对通过表示本机待发提示词包含摘要，模型实际接收仍需真实酒馆验收。
- 默认保留最近 5 楼原文，更早且已被本轮摘要覆盖的普通文本楼层从发送副本中移除；聊天记录和显示保持完整。缺失、失败、被编辑、预算内未能带入摘要的楼层保留原文；工具调用历史和附件保留。Continue 模式按酒馆深度规则额外保留一楼。
- 总摘要按完整摘要块选取，估算预算为当前上下文的四分之一、最多 6000 token；不会为过滤原文而截断对应摘要。生成前只读已有档案，不额外调用摘要 API，也不等待后台摘要队列。
- 摘要关闭、读取失败或无有效摘要时保留原文；聊天或相关开关变化时恢复发送副本并停止这一轮；宿主再次复制消息后也通过 stopGeneration 取消请求。最终提示词缺少完整摘要时同样停止发送。重新发送后使用新状态。
- 每个聊天楼层都有独立记录：缺失、处理中、已摘要、失败。
- 缺失、失败和已完成记录都能单独重新生成。
- 自动摘要只处理之后新增、编辑与滑动重选的楼层，不会在打开插件、启动酒馆或切换聊天时扫完全部旧楼层。旧摘要保留可读；没有完整读取标记的旧记录显示“待核对覆盖”，保留对应原文，点击“补全下一批”后才重新读取并允许过滤。旧楼层由玩家点击“补全下一批”处理，每批可选 10 或 20 楼，默认 10 楼。
- 能完整放入预算的一批楼层调用一次摘要 API，返回后仍拆成逐楼摘要。更大的批次自动拆批；单个长楼层按原文顺序分段完整读取，全部成功后才标记完整覆盖。长总摘要逐段压缩后合并，不省略中段。批次之间默认间隔约 1.8 秒；逐楼摘要或压缩遇到 429 后停止后续批次，已成功的楼层保留。
- 数据库中的来源记录默认展开最近 5 楼，更早楼层默认折叠；展开数量可以在摘要页顶部调整。
- 玩家输入作为完整原文记录保存在本机，并始终带有楼层顺序；它不会因为是决定、拒绝、同意、偏好或边界而获得永久权重。同一主题有后续明确表态时，以更晚楼层为当前状态，旧表态只保留为当时发生过的历史。
- 摘要页可选择剧情选项、推进导演等辅助接口不发送历史原文，或只发送最近 1、3、5 楼；默认不发送历史原文。批量逐楼摘要始终只发送本批目标楼层，不附带批次以外的历史原文。
- 每次请求正文有约 6500 token 的估算上限。逐楼摘要的目标原文和压缩输入完整分批读取；辅助接口及摘要请求所附带的参考历史过长时仍可缩短，不把这类缩短当成目标楼层的完整覆盖。
- 更早的原文只保留在 SillyTavern 与本机 IndexedDB，不由本扩展放入额外 API 请求。
- 摘要页顶部可直接设置自动压缩 token 阈值；每满 100 楼仍会生成一次压缩总摘要。
- 摘要、选项和推进导演可以分别选择酒馆当前 API 或额外 OpenAI-compatible API。
- 额外 API 支持保存多套具名配置，包含完整地址、模型、密钥和嵌入模型。在“设置 → 接口配置”中新建、改名、切换或删除；输入后自动保存。配置及密钥保存在当前浏览器的 `localStorage`，重开后保留，不随聊天档案导出、不跨设备同步；同页扩展仍可能读取。旧地址、模型及仍在本次会话内的密钥会迁移到“默认配置”。已经因关闭浏览器而丢失的旧密钥需要重新填写。模型列表优先从 `/models` 读取，也可手动输入。
- 选中的配置供所有选择“额外 API”的功能使用，包括摘要、大总结、剧情选项、偏好分析、NPC、自主推进和语义回忆；已发出的请求继续使用开始时的配置，之后的请求采用新选择。切换后丢弃旧模型列表返回结果，向量索引按接口、配置和嵌入模型核对。
- 语义回忆默认关闭。开启时先确认当前酒馆提供 `setExtensionPrompt`；开启后只把逐楼摘要、时间线、人物状态、关系和线索发送到额外 API 的 `/embeddings`。在“不发送历史原文”模式下，查询向量也从最近摘要生成，不读取聊天原文。每次酒馆正式生成前，核对摘要与当前楼层指纹，从有效的更早摘要中召回相关内容并通过 `setExtensionPrompt` 注入；界面明确显示等待、本轮已注入、无匹配或注入失败。嵌入模型优先从模型列表中自动选择，也可手动填写。
- 自动推进默认关闭。开启后，以玩家每次发言为起点，最多追加 1—3 轮；发现未发送草稿时停止。关闭开关或停止生成也会作废在途导演结果，重新开启后从下一次玩家发言开始。
- 剧情选项具有独立总开关，默认关闭；支持“玩家行动（代入）”“场景入口”“第三人称叙事”和“混合”四种表达方式，以及 4—12 个选项。点击生成结果只写入 SillyTavern 真实聊天输入框，不触发发送，由玩家自己确认。
- 人格测试的单个答案只保存在当前页面；只有点击“完成测试并生成分析”或主动选择“跳过测试”时才调用分析接口。
- 玩家偏好测试从自主推进主页拆成独立全屏二级页面，包含 10 题情境题和 12 项可多选剧情体验。偏好档案是玩家级全局资料，首次完成后其他聊天直接复用；主页只显示摘要与折叠的完整分析，重新测试前必须确认覆盖，也可以跳过测试直接依据聊天分析。
- 时间线、人物状态、人物关系和伏笔直接展开在每楼摘要下；大总结单独保存连续性规则。
- 打开插件默认进入楼层发送，数据库中的历史楼层可按需展开。手机端保留触摸滚动，隐藏可见滚动条。
- 手机端楼层使用连续档案行而不是独立圆角卡片；底部导航为不透明实体栏，所有入口保持单行显示。偏好测试使用从“不同意”到“同意”的五级连续刻度，中点明确标为“中立 / 不知道”。
- 酒馆聊天界面的“春序”入口使用小型悬浮球；可自由拖动并在本地记住位置，推向右侧边缘可隐藏，点击露出的部分即可恢复。
- 楼层标题、分隔线、状态标记和玩家原文区域使用更柔和的低对比色；手机底部导航单独使用系统楷体字体栈。
- NPC 生成规则位于设置，扩展档案位于数据库。玩家不选择剧情功能，由 AI 根据总摘要、获准发送的近期上下文、现有档案和玩家偏好自行判断。可手动触发建档，也可以在开启后由导演判断是否需要新增人物，并在剧情明确推进时更新既有 NPC 的年龄、人生阶段、工作、客观状态与成长状态。档案用详细经历解释性格和内部矛盾，禁止固定口癖、小动作与行为模板；不生成出场方式或剧情钩子，玩家可以编辑全部档案字段。

## 远端边界说明

剧情选项和推进导演默认构造“当前表格状态＋总摘要”，不附带历史楼层原文；玩家也可以主动改为最近 1、3、5 楼。逐楼摘要必须额外发送目标楼层本身，才能生成该楼摘要。语义索引只使用摘要和结构化事实；零原文模式下，查询向量也只使用摘要。所有上述请求正文合计最多约 6500 token。如果使用酒馆当前 API，其他已安装扩展仍可能在 SillyTavern 的生成事件中修改请求；本扩展无法替第三方扩展作隐私保证。

自动推进分两步：导演接口生成一条推进指令，随后 SillyTavern 当前连接按正常聊天上下文续写。正常续写沿用酒馆本身的上下文策略，不属于额外摘要 API 的五楼边界。

## 旧楼层正则

日常使用直接开启摘要页的“每次回复前发送总摘要”和“过滤已摘要的旧楼层原文”，两项默认开启，无需再导入正则。

`regex/旧楼层不发送-手动备用.json` 是标准酒馆正则：用户输入和 AI 回复、仅修改发送提示词、最小深度 5、替换为空。独立正则无法判断摘要覆盖情况，所以文件默认关闭，仅供手动管理上下文时备用；启用前必须确认较早楼层已由实际发送的摘要或其他记忆完整接替。它不会自动随本扩展关闭，不建议与内置过滤重复开启。

本次实现依据本地 SillyTavern 1.14.0 源码（commit `fbf789fa7480fafe0275b2f79e4384e77ae689a7`）：`public/script.js` 的发送副本及 `index`、`setExtensionPrompt`，`public/scripts/extensions.js` 的 `runGenerationInterceptors`，以及 `public/scripts/extensions/regex/engine.js` 的 placement 和深度判断。均为宿主 API，无需酒馆助手。参考路由：`sillytavern-render-regex-pipeline` / `sillytavern-extension-dev`，库快照 `2026-08-18`，读取 A0/A5/A6/D5，E5 仅用于确认扩展边界。真实酒馆最终请求、第三方扩展顺序和手机操作仍待验收。

正则验证：通用离线校验器错误地要求替换文本非空，因此对清空规则报错；已直接运行上述固定版本的 `getRegexedString` / `runRegexScript`，8 个用例通过（两类消息、深度边界、显示保持、禁用保持、世界书保持）。这是源码函数验证，不等于真实宿主验收。

## 本地验证与使用

- 本轮运行现有检查与新增回归测试，并执行本地 SillyTavern 源码中的提示词组装、附件拼接、停止发送和正则函数；发送端为内存替身，没有真实网络或模型调用。这些检查不等于真实浏览器 IndexedDB、服务器或模型验收。
- 手动安装本地修复包后需刷新酒馆页面。旧记录先保持可读与原文保留；需要恢复旧楼层过滤时，点击“补全下一批”。补全会按所选 API 重新生成摘要，并产生相应模型用量。
- 总摘要和逐楼摘要仍受酒馆自身上下文预算约束。工具调用历史采取保留原文策略。其他扩展可能有独立的旧原文注入，仍需在实际使用环境核对扩展顺序及最终请求。
- 依赖宿主提供 setExtensionPrompt、stopGeneration、GENERATE_AFTER_DATA；缺少停止或最终事件能力时保留原文。最终检查移到当时已有事件监听器末尾；模型收到什么仍须查看实际请求，尤其是其他扩展之后继续修改请求的环境。
