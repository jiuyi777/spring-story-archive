# 喵喵数据库 · 单蓝图

## 目标

让长篇剧情在下一轮继续可用：自动读取新剧情 → 精简事实与表格增量 → 校验 → 按聊天保存 → 续写、选项、NPC、推进共用 → 新回复再次入库。楼层摘要承担历史事实记录；表格承担当前状态，推进承担实际续写。

八类表格由楼层变更与手动修订重建，储存在既有 IndexedDB 档案中。删除、编辑和重选楼层后撤回旧来源。用户修订进入实际发送和语义召回，重新打开继续有效。纯“继续”指令不当剧情总结。

正常续写读取已有成功记忆并保留未覆盖原文；选项和导演等待新剧情入库。配置缺失或入库失败应显示真实原因。世界书同步与自定义表格模板不属于本地 0.6.0 实现。

## 红线

- 不把第六楼以前的原文放进摘要、选项或推进导演请求。
- 不默认开启自动推进。
- 不把 API Key 写入扩展设置、IndexedDB、日志或预览数据。
- 不在玩家输入框有草稿时触发自动推进。
- 不把静态检查称为真实酒馆验收。

## 第一版验收

1. 每个当前聊天楼层在列表中都有状态。
2. 缺失与失败楼层可重新生成。
3. 隐私负载测试证明默认不含历史楼层原文，逐楼摘要仅含目标楼层，且正文受统一 token 上限约束。
4. 第 100 楼或 token 上限触发压缩摘要。
5. 选项支持三种模式与 4—12 个数量。
6. 自动推进必须由玩家开启，并按轮数上限停止。
7. 桌面和 390px 宽手机预览可阅读、可操作。


## 2026-10-09 已确定的界面与调用路径

主导航为数据库 / 楼层发送 / 设置，默认中间页。楼层发送保存每次独立请求：拦截原文范围 → 选中记忆及原因 → 提示词准备 → 最终提示词核对 → 收到回复或停止。重选单列，历史按聊天持久化，不能把准备状态标成模型已接收。

数据库保留八表、搜索、人物与物品/关系关联阅读、折叠编辑、来源楼层和 NPC 扩展档案。设置集中折叠管理；剧情选项的写法、数量与写作要求配置在这里，生成结果挂在酒馆回复正文下方。

表格调用按场景、别名、明确提及、拥有者和关系筛选；保留原有摘要覆盖保护，只有本轮完整带入的已验证摘要才能替代旧原文。宿主 DOM 接入核对本地 SillyTavern 1.14.0 的 #chat .mes[mesid] .mes_text。浏览器测试使用模拟宿主事件和模型响应，不调用真实外部模型。
